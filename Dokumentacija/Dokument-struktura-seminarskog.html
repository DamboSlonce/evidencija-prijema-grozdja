1. Opis namene aplikacije u kontekstu poslovnog procesa i poslovnog pravila

Aplikacija podržava poslovni proces evidencije prijema grožđa u vinariji. Na prijemnom mestu se za svaku turu grožđa meri neto masa, sadržaj šećera, kiselost, temperatura i udeo oštećenih bobica. Podaci se upisuju u dokument Zapisnik o prijemu grožđa. Jedan zapisnik (prijem) može da sadrži više tura (odnos celina–deo, master–detail). Sistem ne obrađuje otkup ni cenu, već merenja kvaliteta i usmerenje prerade.

Poslovno pravilo je parametrizovano i ima oblik AKO uslov ONDA automatska akcija:

AKO je sadržaj šećera u turi (%) manji od minimuma X za tu sortu ILI je udeo oštećenih bobica veći od dozvoljenog Y%, ONDA sistem automatski usmerava turu u destilat (ne dozvoljava usmerenje „kvalitetno vino“).

Parametri odlučivanja X i Y nisu u kodu, već u eksternom XML fajlu OgranicenjaKvaliteta.XML (Rizling: 19% / 10%, Tamjanika: 18% / 10%, Prokupac: 20% / 10%). Poslovna logika ih čita pozivom SOAP servisa, a isti parametri su dostupni i preko REST servisa u JSON formatu.

6. Ključni delovi koda sa objašnjenjem

6.1 Realizacija korisničkih softverskih funkcija

6.1.1 Prijava korisnika

Ruta /Prijava otvara PrijavaController.Index. GET vraća prazan PrijavaViewModel. POST mapira ViewModel na FormaLoginKlasa, koja preko SPKorisnikDBKlasa (stored procedure) proverava nalog. Uspeh: sesija KorisnikImePrezime i redirekcija na /Pocetna. Filter ZahtevaPrijavu štiti ostale kontrolere. 

public ActionResult Index(PrijavaViewModel model)
{
    FormaLoginKlasa forma = new FormaLoginKlasa(this.StringKonekcije);
    forma.KorisnickoIme = model.KorisnickoIme;
    forma.Sifra = model.Sifra;
    bool pronadjen = forma.VazeciKorisnik();
    if (pronadjen)
    {
        Session["KorisnikImePrezime"] = forma.DajImePrezimeKorisnika();
        return RedirectToAction("Index", "Pocetna");
    }
    model.Poruka = "KORISNIK NIJE PRONADJEN!";
    return View(model);
}

6.1.2 CRUD operacije nad glavnom tabelom

Glavna tabela dokumenta je TURA (stavke) uz zaglavlje PRIJEM. TuraController: Unos, Spisak (filter), štampa. PrijemController.Unos: unos celine sa delovima na jednoj formi (stavke u sesiji, zatim transakcija). PrijemController.Prikaz: pojedinačni zapis celine sa svim delovima. Šifarnik SORTA ima pun CRUD u SortaController (Tabelarni, Unos, Izmena, Detalji, Obrisi).

6.1.3 Štampa i parametarska štampa

Pogledi koriste layout _Stampa.cshtml (printer-friendly). /Tura/Stampa?filter=0 — spisak svih tura. /Tura/ParametarStampe — unos isporučioca, zatim filtrirani zapisnik. Izgled tabele odgovara dokumentu sa prijave teme (zaglavlje kolona + stavke + usmerenje).

6.2 Realizacija osnovnih validacija

Na prezentacionoj logici: DaLiJeSvePopunjeno (obavezna polja), provera tipa (decimal.Parse), dužina (maxlength u View), domen (drop-down sorte i usmerenje), jedinstvenost (PK u bazi). Primer — zaglavlje prijema mora imati broj, datum i isporučioca pre snimanja.

6.4 Sloj poslovne logike — realizacija poslovnog pravila

UsmerenjePreradeKlasa.OdrediUsmerenje mapira naziv sorte na šifru servisa (R/T/P), zatim SOAP metodama čita X i Y iz XML-a. Ako je šećer < X ili udeo oštećenih > Y, rezultat je destilat. 

if ((analizaObjekat.SecerProcenat < pomMinSecer) ||
    (analizaObjekat.UdeoOstecenihProcenat > pomMaxUdeoOstecenih))
{
    pomUsmerenje = "destilat";
}
else
{
    pomUsmerenje = "kvalitetno vino";
}

XML parametar (izvod): Rizling <MinSecer>19</MinSecer>, <MaksimalniUdeoOstecenih>10</MaksimalniUdeoOstecenih>.

6.6.4 Rad sa Entity Framework klasama

Entitet SortaEfKlasa mapira tabelu SORTA. Kontekst VinarijaKontekstKlasa nasleđuje DbContext (initializer isključen — baza već postoji). Repository čita kontekst.Sorte.ToList() i snima novi zapis sa SaveChanges. Tabelarni prikaz sorti bez filtera koristi ovaj put. 

public class SortaEfKlasa
{
    public string Sifra { get; set; }
    public string Naziv { get; set; }
}

public class VinarijaKontekstKlasa : DbContext
{
    public DbSet<SortaEfKlasa> Sorte { get; set; }
    protected override void OnModelCreating(DbModelBuilder modelBuilder)
    {
        modelBuilder.Entity<SortaEfKlasa>().ToTable("SORTA");
        modelBuilder.Entity<SortaEfKlasa>().HasKey(s => s.Sifra);
    }
}

6.7 Opciono — Master–detail unos sa transakcijom i tabelarni prikaz

Na formi prijema korisnik dodaje više tura u tabelu u sesiji, zatim snima celinu. PrijemDBKlasa.SnimiPrijemSaTurama pravi listu INSERT naredbi (jedna za PRIJEM, po jedna za svaku TURU) i poziva TabelaKlasa.IzvrsiAzuriranje(listaUpita) — sve ili ništa. Tabelarni prikaz: spisak tura i prikaz svih stavki izabranog prijema.

6.8 Opciono — JavaScript validacije i regularni izrazi

Fajl Scripts/Validacija.js: provera praznih polja, numeričkih vrednosti, izbora iz domena (sorta nije „Izaberite...“). Regularni izraz za broj prijema i oznaku ture (slova, cifre, crtica). Funkcije se vezuju na onsubmit / onclick u Razor pogledima.
